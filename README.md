# 복구봇 관리 시스템

JavaScript, Discord.js, Express, MongoDB Atlas로 구성된 관리자 웹사이트와 메인봇·호기봇 실행기입니다.

## 설정 및 실행

1. Node.js 22.12 이상과 MongoDB Atlas를 준비합니다.
2. `.env.example`을 복사해 `.env`를 만들고 다음 값을 설정합니다.
   - `MONGODB_URI`: Atlas 연결 주소
   - `TOKEN_ENCRYPTION_KEY`: 32바이트 Base64 키
   - `MAIN_BOT_TOKEN`: 자동충전 패널과 승인 기록을 게시할 메인봇 토큰
   - `PUBLIC_BASE_URL`: 인증 버튼에서 접근할 웹사이트 주소. 로컬에서는 `http://localhost:3000`, 배포에서는 HTTPS 주소를 사용합니다.
   - `RECOVERY_DELAY_MS`: 계정 사이 복구 대기 시간(기본 2000ms, 1000~60000ms).
   - `RECOVERY_APPROVAL_CHANNEL_ID`: 메인봇의 라이선스 복구 승인 요청을 받을 관리자 채널 ID.
   - `RECOVERY_LOG_CHANNEL_ID`: 웹사이트 및 라이선스 복구의 성공·실패 결과를 Components V2로 기록할 관리자 전용 채널 ID.
   - `RECOVERY_ADMIN_USER_ID`: 승인·거절 버튼을 사용할 관리자 Discord 사용자 ID. 해당 사용자의 라이선스 명령은 자동 승인됩니다.
3. Discord Developer Portal에서 **각 호기 앱마다** OAuth Redirect URL로 `{PUBLIC_BASE_URL}/oauth/callback`을 등록합니다. 예를 들어 로컬 주소라면 `http://localhost:3000/oauth/callback`입니다.
4. Atlas IP Access List에 실행 서버의 IP를 등록합니다.
5. 관리자 계정을 만들고 실행합니다.

    npm install
    npm run admin:create
    npm run dev

`npm run admin:create`를 터미널에서 실행하면 관리자 아이디와 비밀번호를 직접 입력합니다. 아이디는 3~120자, 비밀번호는 12자 이상이며 비밀번호는 해시로 저장됩니다. 기본 계정이나 웹사이트 회원가입은 없습니다. 이미 사용 중인 아이디는 다시 만들 수 없습니다.

`npm start`와 `npm run dev`는 웹사이트와 메인봇만 실행합니다. 각 호기는 해당 호기 프로젝트에서 개별 실행합니다. 실행기는 어떤 호기 봇 토큰으로도 로그인하지 않습니다.

## 호기 인증과 복구

- `/hosts`에서 호기마다 이름, Discord OAuth Client ID, Client Secret, 봇 토큰을 저장합니다. Client Secret과 봇 토큰은 AES-256-GCM 암호화 저장합니다. 봇 초대 링크는 선택 입력이며, Client ID와 일치하는 Discord OAuth 봇 초대 링크만 허용합니다.
- 각 호기 봇에서 `/auth-panel channel:#채널`을 실행하면 Components V2 인증 패널이 게시됩니다. 유저는 버튼을 눌러 사이트에서 Discord 인증을 마치며, access/refresh token과 유저 정보를 해당 호기에 연결해 저장합니다.
- 각 호기 실행기는 해당 `BotHost` 문서의 `_id`를 `HOST_ID`로 지정해 MongoDB 설정을 읽습니다. 메인봇의 `/recover license:<코드> server_id:<서버 ID>`가 요청과 승인을 담당하고, 실행기는 공용 DB에 호기별 작업을 등록합니다. 각 호기는 자기 작업만 큐에서 가져와 자기 OAuth 앱의 유저 토큰과 자기 봇 토큰으로 실행합니다.
- OAuth 인증은 `identify email guilds.join`을 요청합니다. 각 호기 봇 토큰은 그 호기의 OAuth 앱과 같은 Discord 앱에서 발급되어야 합니다.
- `/recovery`에서 호기를 하나 이상 체크하고 대상 서버 ID를 입력합니다. 실행 전 각 봇이 그 서버에 들어가 있는지와 `Create Instant Invite` 권한을 검사합니다. 복구 작업은 호기별 잠금 큐를 사용하며, 이미 실행 중인 작업은 끝까지 우선합니다. 대기 작업은 단일 호기 작업을 먼저 실행하고, 같은 우선순위에서는 서버 ID가 낮은 작업을 먼저 고릅니다.
- `/licenses`에서 호기와 유효기간을 골라 수동 지급 코드를 만들거나, 상품화 스위치를 켜 판매 상품을 등록합니다. 상품 구매 때에는 활성화된 전체 호기 중 온라인 호기를 후보로 삼고, ACTIVE 인원 합계가 상품 범위에 드는 최소 호기 조합을 배정합니다. 동률이면 마지막 복구 실행이 오래된 조합을 우선합니다.
- 구매 라이선스는 `VC-` 뒤 14자리 숫자로 생성되어 유저의 비공개 메시지와 DM에 표시되고 1회용입니다. 메인봇의 `/recover license:<코드> server_id:<서버 ID>` 명령으로 요청하며, 설정한 관리자 승인 채널에서 승인해야 작업이 큐에 등록됩니다. 각 호기는 앞선 호기 작업이 끝난 뒤 자기 계정만 처리합니다. 첫 거절은 코드를 다시 발급완료로 돌리고 두 번째 거절은 거절됨으로 처리합니다. 미사용 기간이 지나면 만료됨으로 표시됩니다. 복구 대상 전체에 대한 시도를 끝내면 계정별 오류가 있어도 완료로 표시하고, 성공 인원/전체 인원을 함께 보여줍니다. 중간 중단은 실패로 표시하며 라이선스는 재사용되지 않습니다. 이미 대상 서버에 있던 계정은 성공 인원으로 셉니다.
- 웹사이트 복구와 라이선스 복구 결과는 `RECOVERY_LOG_CHANNEL_ID`로 지정한 관리자 전용 채널에 Components V2 성공·실패 로그로 남습니다. 모든 대상 계정의 시도를 끝내면 개별 계정 오류가 있어도 성공이며, 429 중단·봇 오프라인·서버 이탈 등 전체 작업이 끊기면 실패입니다. 두 경우 모두 실제 가입 인원/전체 인원과 원인별 수를 기록합니다.
- 승인 패널과 충전 패널, 인증 패널은 Discord Components V2 메시지입니다.

## 자동충전

- `/auto-recharge`에서 은행명, 계좌번호, 예금주, 최소 금액, Pushbullet 토큰, 입금 알림 앱 이름, 로그 채널 ID와 충전 임베드 내용을 설정합니다.
- 메인봇에서 `/recharge-panel channel:#채널`을 실행하면 충전 신청 버튼이 든 임베드가 게시됩니다. 유저는 버튼으로 입금자명과 금액을 요청합니다.
- 충전 패널의 후기 버튼을 누르면 아직 후기를 작성하지 않은 본인 구매 내역을 고르고, 모달에 1~5점과 내용을 입력해 제출할 수 있습니다. 후기는 구매별 1회만 등록되며, 자동충전 설정의 리뷰 로그 채널에 작성자·상품·구매 일시·별점·내용을 Components V2로 게시합니다.
- Pushbullet Android 알림 미러에서 설정된 앱 이름과 입금 문구 `입금자명님이 금액원을 보냈어요.`가 일치하면, 조건에 맞는 대기 요청 중 가장 먼저 생성된 한 건에만 잔액을 반영합니다. 같은 조건의 나머지 요청은 추가 자동 매칭에서 제외되어 대기 상태로 남고 만료됩니다. 요청마다 충전 로그 채널에 Components V2 메시지 하나를 게시하고, 대기(노랑)·완료(초록)·만료(빨강)에 따라 같은 메시지를 수정합니다.
- 메인봇의 관리자 전용 `/수동충전 유저 금액` 명령어로 유저 잔액을 조정할 수 있습니다. 양수는 충전, 음수는 차감이며, 잔액보다 큰 차감은 거부합니다. 조정 내역은 잔액 변경과 함께 원장에 기록됩니다.
- 라이선스 구매 로그는 자동충전 설정의 구매 로그 채널로 보내며, 복구 승인·거절 요청 채널과 분리됩니다. 공개 구매 로그에는 라이선스 코드를 기록하지 않고, 코드는 구매자에게만 DM과 비공개 응답으로 전달됩니다.
- Pushbullet 알림 미러 종단간 암호화가 켜져 있으면 본문을 읽을 수 없습니다. 서버가 꺼져 있는 동안 실시간 미러 이벤트가 지나가도 자동으로 다시 읽어오지 않습니다. 자동충전을 사용할 때는 실행 프로세스와 네트워크 연결을 계속 유지해야 합니다.

## 웹 페이지

- `/` 메인페이지
- `/hosts` 호기 봇과 OAuth 설정
- `/recovery` 호기 선택 및 서버별 복구 시작
- `/products` 제품 가격
- `/licenses` 직접 발급, 상품화, 라이선스 상태 검색
- `/auto-recharge` 계좌·입금·로그·임베드 설정
- `/data` 호기별 유저 데이터 조회·삭제, 평문 JSON 가져오기/내보내기, 개별 유저 추가

관리자 API와 관리 페이지는 관리자 로그인으로 보호됩니다. `.env`와 실제 Atlas 자격정보는 저장소에 포함하지 마세요. Atlas 연결 문자열이 예시 파일에 들어간 적이 있어 이미 사용 중인 DB 비밀번호는 교체해야 합니다.
